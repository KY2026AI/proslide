# ProSlide Preview QA

HTML 预览生成后读取本文件。先自查，再把预览交给用户确认。

## HTML 自查清单

逐页检查：

- 页面是否为 `1280×720` 的 `.slide`
- 标题是否完整位于顶部横线以上
- 顶部横线是否与内容区左右对齐
- logo 是否存在、加载成功、没有拉伸变形
- 是否有核心观点条/结论条
- 主内容是否与核心观点对齐
- 是否存在纯大段文字堆叠
- 是否存在文字溢出、裁切、重叠或被图片遮挡
- 图片是否完整显示，是否存在破图
- 字号是否满足最低要求，后排投影是否可读
- 卡片、列、时间线、图表是否网格对齐
- 是否有低对比度文字或过浅图标
- 是否有过多留白或内容过度拥挤

## 浏览器预览

优先使用浏览器打开 HTML 预览。若环境不允许直接打开 `file://`：

1. 启动本地只读 HTTP 服务。
2. 打开本地 URL。
3. 截图或描述预览状态。
4. 不要因此跳过用户确认。

## 固定交付话术

HTML 预览完成后，用类似格式回复：

```md
HTML 预览已生成：[文件路径]
我已做过基础预览检查：页面尺寸、图片加载、文字溢出、标题位置、核心观点条均已检查。

请确认：这版 HTML 预览是否需要调整？
同时请确认是否需要生成讲稿：需要 / 不需要。
```

## 用户反馈处理

- “留白多”：先加大行高、gap、padding，再放大字号；必要时补充图标或强化主指标。
- “太挤”：先压缩文案和合并层级，再收窄 padding/gap，最后才降低字号。
- “文字罗列”：改成卡片、时间线、流程图、对比栏或数据卡片。
- “重点不突出”：增加核心观点条、主指标、状态标签、颜色对比。
- “图片不好看/看不清”：优先完整显示原图，必要时放大图片区或拆到单独页。
- “表达不准确”：只改用户指出的含义，不擅自编造事实。

修改后必须重新生成 HTML 预览，并再次等待用户确认。
