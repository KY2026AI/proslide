# ProSlide Layout Pattern Library

本文件在生成 HTML 前按需读取。它不是模板截图库，也不要求复刻某个 PPT 页面；它用于把素材内容转化为“内容关系 -> 版式选择 -> 禁用条件”的判断。

核心原则：先判断内容关系和信息密度，再选择主版式。一页最好只有一种主结构；视觉变化应服务阅读顺序、证据关系和会议室可读性。

## 使用方式

1. 先给每页标注主关系：并列、对比、递进、分解、时间计划、分析框架、数据证据、问题方案、案例叙事。
2. 判断信息密度：每项是短句、长段、同构字段、非同构字段、还是数据密集。
3. 选择一个主版式，再决定是否需要一个小型辅助模块，例如状态标签、旁注、判断条件或下一步动作。
4. 如果选出的版式需要大量空卡片、装饰图形或固定等高容器才能成立，换版式。

## 关系触发器

| 内容信号 | 优先版式 | 避免 |
|---|---|---|
| 首先/其次/包括/多个要点/几个方面 | 紧凑并列、条形组、图标短句列、2xN 同构网格 | 低信息量等高大卡片 |
| 前后/对比/差异/VS/现状/目标/优劣/方案 A/B | 双栏对比、前后变化带、指标矩阵、差异表 | 两个孤立大卡片 |
| 步骤/阶段/路径/递进/从 A 到 B/演进 | 流程条、阶梯、路径图、阶段门 | 普通项目符号列表 |
| 计划/排期/月/周/里程碑/节奏/推进 | 时间线、甘特图、泳道、周计划矩阵 | 普通清单页 |
| 构成/拆解/模块/能力/组织/责任 | 总分结构、能力地图、树状结构、泳道 | 头像装饰或散点式卡片 |
| 原因/影响/措施/归因/问题 | 鱼骨图、问题树、原因-动作映射 | 只列问题不列归因 |
| SWOT/PEST/PDCA/5W2H/RACI/OKR | 框架专属布局 | 普通四卡片 |
| 数据/指标/%/增长/下降/达成率/趋势 | 图表证据链、大数字 + 小图、指标带、小倍数图 | 孤立图表或无结论图表 |
| 案例/实践/启发/经验/迁移 | 案例链路、问题-做法-效果-启发 | 只罗列案例名称 |

## 并列关系

并列不等于卡片。只有当每项字段完整、层级一致、需要独立阅读时，才使用卡片网格。

推荐：

- 3-5 个短要点：横向条形组、图标短句列、编号步骤带。
- 4-8 个同构信息：2xN 紧凑网格，卡片高度由内容决定。
- 每项包含标题、解释、指标或案例：卡片网格。
- 信息长短差异大：左右分组、主次结构或横向条目，不强行等高。

检查点：

- 每个并列项是否回答同一类问题。
- 是否存在短内容被撑满大容器。
- 图标是否表达对象或动作，而不是装饰。

## 对比关系

对比页的目标是让差异一眼可见，不是把两组文字并排放置。

推荐：

- 前后变化：左“现状/改造前”，右“目标/改造后”，中间用变化箭头或关键指标连接。
- 方案选择：顶部列方案，左侧列比较维度，形成指标矩阵。
- 优劣分析：用同构字段，例如成本、周期、风险、收益、适用条件。
- 正反观点：用深浅、冷暖或标签区分，但不要使用强烈装饰对撞。

检查点：

- 对比维度是否一致。
- 是否有明确判断或选择建议。
- 是否能看出“差异导致什么业务影响”。

## 递进关系

递进页要呈现顺序、升级或因果推进，适合流程、方法论和培训分享。

推荐：

- 线性步骤：横向流程条。
- 阶段升级：阶梯或上升路径。
- 方法论：问题 -> 方法 -> 动作 -> 结果。
- 培训分享：观察现象 -> 拆解难点 -> 提出方法 -> 案例迁移。

检查点：

- 每一步是否有动作动词。
- 是否能看出前后依赖。
- 最后一段是否回收到业务结果或迁移启发。

## 分解关系

分解页用于把复杂对象拆清楚，适合组织、能力、原因、责任和系统模块。

推荐：

- 总分结构：顶部总观点，下方按层级拆解。
- 能力拆解：中心主题 + 周边模块，或能力地图。
- 原因分析：鱼骨图、问题树、原因-影响-措施映射。
- 责任关系：泳道或 RACI 矩阵。

检查点：

- 拆解维度是否互斥、完整、同层级。
- 叶子节点是否足够具体。
- 是否把“原因、影响、动作”混在同一级。

## 时间计划

计划页要表现节奏、依赖和状态，不要变成普通列表。

推荐：

- 项目计划：甘特图或阶段带。
- 里程碑汇报：时间线 + 状态标签 + 风险提示。
- 多团队协同：泳道图。
- 短周期安排：周计划矩阵。

检查点：

- 是否有时间单位和阶段边界。
- 是否标出关键里程碑、负责人或状态。
- 是否能看出当前进度与下一步。

## 分析框架

遇到明确框架关键词时，使用框架专属布局；框架不是装饰，而是帮助受众理解分析逻辑。

推荐：

- SWOT：固定四象限，并加一条战略判断或下一步选择。
- PEST / 5W2H：框架格 + 关键结论。
- PDCA：四阶段闭环，突出改进循环。
- RACI：责任矩阵，明确 Responsible / Accountable / Consulted / Informed。
- OKR：目标树或目标-关键结果映射。

检查点：

- 框架每格是否有真实内容，而不是占位词。
- 是否补充了框架之外的结论。
- 是否避免把框架页做成孤立概念说明。

## 数据图表

图表页要形成证据链：观点、主图、旁注、口径、动作。涉及图表生成或审查时仍必须调用 `proslide-chart`。

推荐结构：

- 页面观点：这组数据说明什么。
- 主图：承载主要比较、趋势、占比或分布。
- 关键旁注：标出峰值、异常、变化幅度、风险点。
- 口径说明：时间范围、单位、数据来源。
- 业务动作：根据数据需要调整什么。

检查点：

- 图表是否支撑核心观点。
- 是否只保留必要图例、网格线和标签。
- 是否存在口径不一致或量纲混用。

## 反模式

- 为了好看而复刻模板截图。
- 所有页面都使用卡片阵列。
- 低信息量内容撑满大卡片。
- 用数字、字母、中文字符或 emoji 伪装图标。
- 图表只有视觉，没有结论、旁注和口径。
- 框架页只有框架，没有判断。
- 时间计划页只有事项，没有节奏、状态或里程碑。
- 只做颜色和形状变化，没有改变信息结构。
