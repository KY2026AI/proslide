# ProSlide Layout Rules

生成 HTML 前读取本文件。主 `SKILL.md` 控制流程，本文件只控制版式与表达。

## 固定页面规格

```css
.slide { width: 1280px; height: 720px; background: #FFFFFF; }
.content-area {
  position: absolute;
  top: 100px; left: 45px; right: 45px; bottom: 28px;
  display: flex; flex-direction: column; gap: 10px;
}
```

每页必须包含：

- 顶部横线：`top: 85px; left: 45px; right: 45px; height: 3px; background: #001E50`
- 右上角 logo：优先查找工作目录中的 `logo.png/jpg/jpeg/svg/webp`。默认建议 `top: 12px; right: 58px; width: 102px; height: 62px; object-fit: contain`，确保 logo 底部完整位于顶部横线上方且不要过度贴近页面顶部。
- 页面标题：`top: 22px; left: 60px; font-size: 30-34px; color: #001E50`
- 核心观点条/结论条：作为本页第一视觉结论，禁止直接进入罗列

## 顶部元素约束

- 标题必须完整位于顶部横线以上；标题区域底部不得超过 82px。
- logo 必须完整位于顶部横线上方，不得覆盖或贴住横线；logo 底部与横线顶部建议保留约 10px 安全间距。若横线为 `top: 85px`，logo 底部建议不超过 75px。
- 不要为了避开 logo 而缩短顶部横线。顶部横线应保持与内容区左右对齐（默认 `left: 45px; right: 45px`）；若 logo 与横线冲突，优先缩小或上移 logo。
- 标题较长时降低字号，最低 22px；禁止擅自插入 `<br>` 改写标题。
- 核心观点条默认左对齐，写成管理汇报式判断句，避免空泛口号。
- 核心观点字号 ≥ 15px，高密度页可用 15-16px，但必须用色块/加粗/编号增强识别。

## 内容类型与版式

先识别内容关系，再选版式：

| 内容类型 | 识别关键词 | 推荐版式 |
|---|---|---|
| 并列关系 | 首先/其次/包括/以及/数字列表 | 卡片式网格 |
| 对比关系 | vs/对比/差异/前后/优劣 | 左右双栏对比 |
| 总分层级 | 总述/具体/整体/部分/核心主题 | 顶部结论 + 分层模块 |
| 流程时间线 | 第一步/然后/阶段/流程/历程 | 横向时间线或步骤流 |
| 数据指标 | 数字+单位/%/增长/下降/KPI | 大数字 + 图表/数据卡片 |
| 问题方案 | 痛点/挑战/问题/对策/措施 | 问题区 + 方案区 |
| 矩阵象限 | 四象限/SWOT/矩阵/坐标 | 2×2 矩阵 |
| 漏斗结构 | 漏斗/筛选/转化/递减 | 倒梯形漏斗 |
| 分析框架 | PDCA/PEST/5W2H/RACI/OKR | 框架专属布局 |

## 信息表达规则

- 禁止纯大段文字逐行罗列。必须自动拆分、提炼、模块化。
- 同级信息必须同构呈现：同样的卡片结构、标签样式、图标规则。
- 数据必须分层：识别 2-3 个主指标，主指标字号 ≥ 30px；次指标缩小。
- 长句超过 15 字时，在句首增加 2-4 字加粗锚点，帮助扫读。
- 关键数字用 `#00B0F0` 或深蓝加粗突出，可配浅蓝标签背景 `#E8F4FC`。
- 中英双语时，英文应位于中文下方或右侧；禁止英文置于中文上方。
- 禁止无意义装饰素材；每个图标/图片/图表必须服务内容语义。

## 字号与可读性

- 页面标题 ≥ 24px
- 核心观点 ≥ 15px
- 卡片标题 ≥ 14px
- 正文 ≥ 13px
- 数据数字 ≥ 24px
- 数据标签 ≥ 11px
- 辅助说明 ≥ 10px
- 状态标签 ≥ 10px

字号下限是硬约束。内容无法在字号下限内自然排布时，按“精简文案 → 重组层级/版式 → 拆页”处理，禁止缩小字体强塞。

## 布局与留白

- 逻辑相关内容要聚拢；段间距必须大于行间距。
- 多列布局按内容密度分配列宽，禁止无脑 `1fr 1fr 1fr`。
- 内容长度差异大时，禁止使用等高竖卡；改用横向条形布局或自适应卡片。
- 卡片型组件内容明显少于容器高度时，优先垂直居中；检查范围不限于 `.card`，也包括条目行、指标块、结论块、流程节点等。
- 布局前先评估信息量、字段数和文本长度，不预设列数或卡片数量；根据最低可读字号动态选择分组、版式或分页。
- 禁止套用模板化布局。先判断内容关系，再选择版式；机械三卡片、等宽空卡、泛化图标堆叠等“AI味”布局必须重排。
- 高密度页先收窄 padding/gap，再考虑缩字号。
- 禁止用 `margin-top: auto`、`justify-content: space-between` 硬拉内容。
- 禁止固定高度导致文字溢出；文本容器不要依赖 `overflow: hidden` 截断。
- 字号偏小且同时存在大块连续空白，说明空间分配失衡，必须重排；完整渲染不等于适合汇报。
- 出现明显留白时，先判断能否加入语义信息图：流程示意、关系图、场景链路、数据卡片、关键图标组、简化系统架构图。信息图必须解释内容关系，不能只是装饰。
- 禁止用孤立的大空白卡片、中文标号、数字圆点、字母圆点来“填版式”。这些只算占位，不算视觉表达。

## 图片与图表

- 用户提供的配图必须完整显示，使用 `object-fit: contain`。
- 图片容器应设置 `overflow: hidden`，但不得裁切主体。
- 图表需求必须调用 `proslide-chart`。
- 数据密集型页面优先信息图/图表/数据卡片，表格只用于精确对比。

## 图标与配色

- 图标采用 Lucide 风格线性图标或等价简洁 SVG。
- 图标必须语义匹配，禁止装饰性图标。
- 禁止把中文、英文字母、数字、emoji 放进圆角块里冒充图标。若要表示步骤，步骤编号可以作为辅助标签，但旁边仍应有真正的语义 SVG 图标；如果空间不足，宁可只保留 SVG 图标。
- 图标尺寸、线宽、颜色要统一；同一页内不要混用线性图标、实心图标、文字图标。
- 主色：`#001E50`
- 辅助蓝：`#00B0F0`
- 风险红：`#C00000`
- 党建类主视觉使用 `#C00000`
- 禁止无意义渐变；核心观点条优先纯色浅底，如 `#F0F4FA`、`#F2F2F2`。
