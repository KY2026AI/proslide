# ProSlide Layout Rules

生成 HTML 前读取本文件。主 `SKILL.md` 控制流程，本文件只控制版式与表达。

## 固定页面规格

```css
.slide { width: 1280px; height: 720px; background: #FFFFFF; }
.content-area {
  position: absolute;
  top: 100px; left: 45px; right: 45px; bottom: 28px;
  display: flex; flex-direction: column; gap: 10px;
}
```

每页必须包含：

- 顶部横线：`top: 85px; left: 45px; right: 45px; height: 3px; background: #001E50`
- 右上角 logo：优先查找工作目录中的 `logo.png/jpg/jpeg/svg/webp`。默认建议 `top: 12px; right: 58px; width: 102px; height: 62px; object-fit: contain`，确保 logo 底部完整位于顶部横线上方且不要过度贴近页面顶部。
- 页面标题：`top: 22px; left: 60px; font-size: 30-34px; color: #001E50`
- 核心观点条/结论条：作为本页第一视觉结论，禁止直接进入罗列

## 顶部元素约束

- 标题必须完整位于顶部横线以上；标题区域底部不得超过 82px。
- logo 必须完整位于顶部横线上方，不得覆盖或贴住横线；logo 底部与横线顶部建议保留约 10px 安全间距。若横线为 `top: 85px`，logo 底部建议不超过 75px。
- 不要为了避开 logo 而缩短顶部横线。顶部横线应保持与内容区左右对齐（默认 `left: 45px; right: 45px`）；若 logo 与横线冲突，优先缩小或上移 logo。
- 标题较长时降低字号，最低 22px；禁止擅自插入 `<br>` 改写标题。
- 核心观点条默认左对齐，写成管理汇报式判断句，避免空泛口号。
- 核心观点字号 ≥ 15px，高密度页可用 15-16px，但必须用色块/加粗/编号增强识别。

## 内容类型与版式

先识别内容关系，再选版式。卡片只是并列信息的一种组件，不是默认页面骨架；除非内容确实是同级并列、字段完整且每项信息密度相近，否则不要优先使用卡片式网格。

不要学习或复刻某个模板截图的外观。应把模板素材抽象为“内容关系、信息密度、主结构、禁用条件”，并保持 ProSlide 的统一页眉、logo、顶部横线、核心观点条、主色和可读性规则。

| 内容类型 | 识别关键词 | 推荐版式 |
|---|---|---|
| 并列关系 | 首先/其次/包括/以及/多个方面/数字列表 | 紧凑条目组、分组清单、图标短句列、2xN 同构网格；信息密度足够时才用卡片网格 |
| 对比关系 | vs/对比/差异/前后/现状/目标/优劣/方案A-B | 左右双栏对比、前后变化带、差异表、指标矩阵 |
| 递进关系 | 步骤/阶段/路径/递进/演进/从...到... | 横向流程条、阶梯路径、阶段门、方法链 |
| 总分层级 | 总述/具体/整体/部分/核心主题/模块/能力 | 顶部结论 + 分层模块、金字塔、树状拆解、能力地图 |
| 时间计划 | 计划/排期/月/周/里程碑/节奏/推进 | 时间线、甘特图、泳道图、周计划矩阵 |
| 数据指标 | 数字+单位/%/增长/下降/KPI/达成率/趋势 | 大数字 + 图表、指标带、小倍数图、数据证据链 |
| 问题方案 | 痛点/挑战/问题/原因/影响/对策/措施/责任 | 问题-原因-动作映射、左问题树 + 右方案区、优先级矩阵 |
| 案例叙事 | 案例/实践/启发/经验/迁移 | 问题-做法-效果-启发链路、案例对照、迁移句 |
| 矩阵象限 | 四象限/SWOT/矩阵/坐标 | 2x2 矩阵 + 结论判断 |
| 漏斗结构 | 漏斗/筛选/转化/递减 | 倒梯形漏斗 + 阶段口径 |
| 分析框架 | SWOT/PDCA/PEST/5W2H/RACI/OKR | 框架专属布局、环形闭环、责任矩阵、目标树 |

### 版式触发器

若页面命中以下信号，优先使用对应主版式，而不是先拆成卡片：

- **前后/现状/目标/差异**：使用对比版式，并明确差异带来的业务影响。
- **步骤/阶段/路径/递进**：使用流程条、阶梯或路径图，并让每一步有动作动词。
- **计划/月/周/里程碑/推进**：使用时间线、甘特或泳道，并标出状态、责任或下一步。
- **原因/影响/措施/责任**：使用问题树、鱼骨图或原因-动作映射，不要只列现象。
- **SWOT/PDCA/RACI/OKR 等框架词**：使用框架专属布局，并补充框架外的结论判断。
- **数据/%/趋势/达成率**：使用图表证据链，页面观点、主图、旁注、口径和业务动作要互相支撑。
- **案例/经验/启发**：使用“问题是什么 -> 做法是什么 -> 效果是什么 -> 可迁移启发是什么”的叙事链。

### 版式选择优先级

1. **先判断关系**：流程、对比、因果、层级、数据、矩阵、案例等关系优先匹配专属版式；不要把所有内容都拆成等宽卡片。
2. **再判断密度**：每项只有短标题或 1-2 行说明时，优先使用条形、标签组、步骤带、信号组或图文映射，而不是大卡片。
3. **最后才用卡片**：只有当并列信息字段完整、层级一致、每项需要独立阅读时，才使用卡片式网格。
4. **避免截图模板思维**：不要因为某个模板页好看就复刻外观；只吸收结构逻辑，例如“对比维度一致”“时间有里程碑”“图表有旁注”。
5. **整稿要有变化**：连续 3 页以上都是卡片网格时，必须重新检查是否可以改成对比页、流程页、数据页、矩阵页、案例页或路径页。
6. **页面主形态要清楚**：一页最好只有一种主版式，例如“时间线 + 证据条”“对比双栏 + 结论带”“问题树 + 措施映射”，避免堆多个卡片区。

## 信息表达规则

- 禁止纯大段文字逐行罗列。必须自动拆分、提炼、模块化。
- 同级信息必须同构呈现：同样的卡片结构、标签样式、图标规则。
- 数据必须分层：识别 2-3 个主指标，主指标字号 ≥ 30px；次指标缩小。
- 长句超过 15 字时，在句首增加 2-4 字加粗锚点，帮助扫读。
- 关键数字用 `#00B0F0` 或深蓝加粗突出，可配浅蓝标签背景 `#E8F4FC`。
- 中英双语时，英文应位于中文下方或右侧；禁止英文置于中文上方。
- 禁止无意义装饰素材；每个图标/图片/图表必须服务内容语义。
- 输出内容必须保持正式汇报语气：克制、准确、清晰，适合会议室呈现；不要过度口语化、聊天化或使用网络化表达。
- 同时避免浓重“AI味”。少用空泛套话、万能口号和过度抽象词，例如“赋能闭环、生态矩阵、全域协同、智能中台、价值跃迁、重塑范式、打造抓手”等；除非用户素材明确使用且业务场景需要。
- 减少行业黑话和圈内术语堆叠。必须使用专业术语时，第一次出现要用简洁、正式的业务解释说明含义，或用“术语 + 管理含义 / 业务影响”的方式表达。
- 页面标题和核心观点优先写具体对象、动作、变化或判断，不写泛化口号。将“AI驱动办公效能跃迁”改为“AI提升材料整理、检查和数据分析效率”这一类更适合汇报的表达。
- 每页至少检查一次“非本领域同事能否理解”。如果需要连续解释多个术语才能理解，应改写为正式但易懂的业务场景、具体问题或案例语言。

## 字号与可读性

- 页面标题 ≥ 24px
- 核心观点 ≥ 15px
- 卡片标题 ≥ 14px
- 正文 ≥ 13px
- 数据数字 ≥ 24px
- 数据标签 ≥ 11px
- 辅助说明 ≥ 10px
- 状态标签 ≥ 10px

字号下限是硬约束。内容无法在字号下限内自然排布时，按“精简文案 → 重组层级/版式 → 拆页”处理，禁止缩小字体强塞。

## 布局与留白

- 逻辑相关内容要聚拢；段间距必须大于行间距。
- 多列布局按内容密度分配列宽，禁止无脑 `1fr 1fr 1fr`。
- 不要把卡片式网格作为默认排版。先尝试更贴合内容关系的版式：时间线、双栏对比、问题-方案映射、矩阵、路径图、指标带、案例叙事、图表证据链。
- 整份 HTML 预览中，卡片页应与流程页、对比页、数据页、矩阵页、图文页等混合出现；如果多数页面第一眼都是圆角块阵列，判定为模板感偏强，必须重排部分页面。
- 内容长度差异大时，禁止使用等高竖卡；改用横向条形布局或自适应卡片。
- 卡片不是背景框，容器大小必须跟信息量匹配。低信息量卡片（标题 + 1-3 行正文 / 1-3 个 bullet / 单个短结论）禁止使用 `flex: 1`、大 `min-height`、等高网格或固定高度强行撑满页面。
- 卡片型组件内容明显少于容器高度时，优先缩短容器、改成横向条形/紧凑流程/自适应卡片，并让内容垂直居中；检查范围不限于 `.card`，也包括条目行、指标块、结论块、流程节点等。
- 内容实际高度低于容器高度约 50% 时，判定为空间分配失败；低于约 40% 时判定为 L1 硬伤，必须重排，不能交给用户确认。
- 三卡片流程、四卡片并列、2×2 矩阵等常见版式在信息量少时必须压缩高度；页面剩余空间应用于语义补充，例如判断信号、流程关系、适用条件、案例迁移、风险边界或简化信息图。
- 布局前先评估信息量、字段数和文本长度，不预设列数或卡片数量；根据最低可读字号动态选择分组、版式或分页。
- 禁止套用模板化布局。先判断内容关系，再选择版式；机械三卡片、等宽空卡、泛化图标堆叠等“AI味”布局必须重排。
- 高密度页先收窄 padding/gap，再考虑缩字号。
- 禁止用 `margin-top: auto`、`justify-content: space-between`、`align-content: stretch` 或 `height: 100%` 硬拉内容；只有当卡片内有足够信息且视觉关系需要等高时，才允许等高。
- 禁止固定高度导致文字溢出；文本容器不要依赖 `overflow: hidden` 截断。
- 字号偏小且同时存在大块连续空白，说明空间分配失衡，必须重排；完整渲染不等于适合汇报。
- 出现明显留白时，处理顺序固定为：先缩短/压缩容器 → 再改版式（条形、流程、对比、信号组、信息图）→ 再补充语义信息 → 最后才考虑调整字号。补充内容必须解释页面观点，不能只是装饰。
- 若补充语义信息，优先选择能帮助迁移理解的内容：为什么适用、判断条件、输入-规则-输出、风险边界、下一步动作、案例启发。禁止补空泛口号。
- 禁止用孤立的大空白卡片、中文标号、数字圆点、字母圆点来“填版式”。这些只算占位，不算视觉表达。

### 低信息量卡片处理规则

当某一组卡片每张只有少量文本时，按以下方式处理：

1. **流程类**：改成紧凑横向流程条，卡片高度通常不超过内容高度的 1.8 倍；下方可补“判断信号 / 适用条件 / 迁移启发”。
2. **并列类**：改成横向条目、两列紧凑卡、图标 + 短句列表，避免大面积等高卡。
3. **案例类**：补“问题是什么 → 做法是什么 → 效果/启发是什么”的语义链路，而不是把案例点放进空卡。
4. **概念解释类**：使用密度更高的卡片网格或词典式条目；不要让 6 个短定义占满整页高度。
5. **仍然留白明显时**：拆分叙事或增加可解释的信息图；若没有可补内容，就缩小该模块并增加页面留白节奏，不要制造空框。

## 图片与图表

- 用户提供的配图必须完整显示，使用 `object-fit: contain`。
- 图片容器应设置 `overflow: hidden`，但不得裁切主体。
- 图表需求必须调用 `proslide-chart`。
- 数据密集型页面优先信息图/图表/数据卡片，表格只用于精确对比。

## 图标与配色

- 图标采用 Lucide 风格线性图标或等价简洁 SVG。
- 图标必须语义匹配，禁止装饰性图标。
- 禁止把中文、英文字母、数字、emoji 放进圆角块里冒充图标。若要表示步骤，步骤编号可以作为辅助标签，但旁边仍应有真正的语义 SVG 图标；如果空间不足，宁可只保留 SVG 图标。
- 图标尺寸、线宽、颜色要统一；同一页内不要混用线性图标、实心图标、文字图标。
- 主色：`#001E50`
- 辅助蓝：`#00B0F0`
- 风险红：`#C00000`
- 党建类主视觉使用 `#C00000`
- 禁止无意义渐变；核心观点条优先纯色浅底，如 `#F0F4FA`、`#F2F2F2`。
